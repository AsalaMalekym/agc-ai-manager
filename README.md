# AG|C AI Manager 3.0

Автономный администратор сообщества ВК. Рабочий Worker: `vkgropwithgpt`.
Панель: https://vkgropwithgpt.woen2017.workers.dev/
Callback: https://vkgropwithgpt.woen2017.workers.dev/vk/callback

## Возможности

- Восемь оригинальных постов в день: 08:00, 10:00, 12:00, 14:00, 16:00, 18:00, 20:00, 22:00 МСК.
- DeepSeek создаёт текст и отдельным запросом проверяет текст/описание картинки. Некорректный ответ или сбой проверки блокирует публикацию.
- Ответы в личных сообщениях сообщества и на обращения/вопросы в комментариях. Входящий текст и ответ проверяются независимо.
- Модерация комментариев работает независимо от автоответов. При reject с уверенностью >= 0.98 возможно удаление; сомнительное — в список проверки. Бан пользователей не выполняется.
- Вложения в комментариях отправляются на ручную проверку: текстовая модель их не видит. Мат и несогласие сами по себе не считаются нарушением.
- Ежедневная аналитика в 23:30 МСК: последние 100 записей, просмотры, реакции, комментарии, репосты. Это не уникальный охват и не статистика всех подписчиков.
- Выбор предпочтительной темы на основе своих постов: минимум три поста с 50+ просмотрами на тему. Расписание и частота не меняются.
- Тренды из максимум пяти заданных сообществ ВК (`TREND_GROUP_IDS`). Это не поиск по всему интернету; без списка источников тренды не собираются.
- Необязательные оригинальные иллюстрации через Workers AI FLUX (`GENERATE_IMAGES=on`). Текст мемов находится в подписи; генерация текста внутри изображения не обещается. Проверяется описание, но отдельной визуальной модерации результата нет: функцию следует включать только после проверки качества.
- Панель с остановкой/возобновлением, черновиком, аналитикой, журналом и списком комментариев на проверку. Ключ не сохраняется в браузере.

## Надёжность

SQLite Durable Object сериализует очередь для группы; запись задачи и ключа дедупликации атомарна. Callback получает `ok` только после сохранения. Повторные события не порождают повторных заданий. VK получает постоянный `guid`/`random_id`.

Задание получает статус processing до сетевых вызовов. После обрыва или неопределённого результата отправки автоматического повтора нет: сервис останавливается для проверки журнала/стены. Это намеренная стратегия «лучше пропуск, чем дубль», не обещание exactly-once во внешнем API. Пропущенные/просроченные (>15 минут) слоты не догоняются.

STOP хранится в Durable Object и проверяется непосредственно перед записью в ВК. Уже отправленный HTTP-запрос отозвать нельзя. Возобновление удаляет накопленные ожидающие задания, чтобы не отправить их пачкой.

Три ошибки подряд или исчерпание лимита ИИ открывают автоматическую остановку. По умолчанию максимум 250 запросов DeepSeek в сутки UTC (это лимит запросов, не рублей); 10 событий на пользователя и 100 всего в час, очередь до 100. При лимите пользователя событие пропускается. История — 60 постов, журнал — 200 записей, проверка — 100 комментариев, дедупликация — 30 дней. Исходные сообщения удаляются после завершения задачи.

Секреты и ответы API с request_params в журнал не попадают. Пользовательский текст не может задавать метод API, получателя, ссылку загрузки или настройки.

## Настройки рабочего Worker

Существующие секреты и неописанные переменные сохраняются (`keep_vars=true`). Другие Workers и DNS не изменяются. Старый KV не удаляется; новая очередь изолирована в Durable Object. Отдельный staging больше не участвует в рабочем развёртывании.

| Имя | Назначение |
| --- | --- |
| `DEEPSEEK_API_KEY` | Секрет DeepSeek |
| `DEEPSEEK_MODEL` | Модель, по умолчанию `deepseek-chat`; можно сохранить существующую |
| `VK_GROUP_ID` | Положительный числовой ID группы |
| `VK_TOKEN` | Токен сообщества для сообщений, комментариев, чтения стены |
| `VK_USER_TOKEN` | Пользовательский токен администратора с правами wall/photos: публикации, удаление комментариев, загрузка изображений |
| `VK_CALLBACK_SECRET` | Секрет сервера Callback API, одинаковый в VK и Worker |
| `VK_CONFIRMATION_CODE` | Строка подтверждения сервера VK |
| `AGC_ADMIN_KEY` | Случайный секрет панели, минимум 24 символа; совместимость с прежним `AGC_TEST_KEY` |
| `KILL_SWITCH` | Только `off` разрешает автоматическую работу; отсутствие или другое значение останавливает |
| `GENERATE_IMAGES` | `on` включает Workers AI и загрузку иллюстраций; по умолчанию выключено |
| `TREND_GROUP_IDS` | Положительные ID источников через запятую; необязательно |

`wrangler.toml` включает рабочие AUTO_POST, AUTO_REPLY, COMMENT_REPLY, MODERATION и AUTO_DELETE. Для остановки используй панель или `KILL_SWITCH=on`. Публикации требуют VK_USER_TOKEN: токен сообщества не заменяет пользовательский для user-only методов VK. Если нужного секрета нет, код не может создать его самостоятельно.

В настройках Callback API ВК нужны события `message_new` и `wall_reply_new`, включённые сообщения сообщества и указанный секрет. Проверка секрета действует и для подтверждения сервера.

Секреты вводятся через Cloudflare → Worker → Settings → Variables and Secrets либо `npx wrangler secret put ИМЯ --config wrangler.toml`. Не помещай их в GitHub-файлы, URL, скриншоты или переписку.

## Развёртывание и проверка

GitHub Actions `Deploy AGC Production` запускается при изменении main или вручную. Он использует существующие `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` из окружения production, запускает все тесты, собирает Worker, развёртывает **wrangler.toml**, проверяет live /health, панель и отказ неавторизованным запросам.

```sh
npm ci
npm run check
npx wrangler deploy --dry-run --config wrangler.toml
npm run smoke
```

Тесты охватывают конкурентные callback, расписание, неверный секрет/группу/JSON, лимит тела, модерацию, выключенные функции, дубли, STOP во время генерации, сбой сети после отправки, рестарт Durable Object, лимиты расходов, аналитические расчёты, защиту загрузки изображения и настоящий runtime workerd с SQLite.

Provider-запросы в unit-тестах подменяются. Это не проверка баланса DeepSeek, действительности токенов VK, прав администратора или наличия VK-событий. Для живой диагностики панель вызывает `/test-ai` и `/api/analytics`; черновик проходит генерацию и модерацию, но не публикуется.

Health содержит только признаки настройки, не секреты. `postingActive` означает включённую конфигурацию и наличие секретов, не подтверждённое право VK на wall.post. Реальная успешная публикация фиксируется как `published` с postId.

`TEST_POST` из старой версии больше не используется — случайный тестовый пост по cron невозможен. `worker.test.js` удалён: он был отдельным Worker, а не набором тестов. Его маршрут `/test-ai` встроен в основной защищённый сервис.

## Откат

Верни предыдущую версию Worker через Cloudflare Deployments. Не удаляй Durable Object/SQLite миграцию или старый KV во время отката. Для срочного прекращения внешних действий сначала нажми STOP или установи KILL_SWITCH=on.
